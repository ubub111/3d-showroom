# Техническое задание: универсальный 3D-магазин / конфигуратор

**Версия:** 0.1, 13 ноября 2026 года  
**Назначение:** быстрый демонстрационный проект для Александра Геннадьевича, с дальнейшей возможностью развить его в коммерческий продукт.  
**Срок для показа первой версии:** ориентир — 1–2 недели при наличии 3D-моделей и данных. Это оценка для демо, не обещание готового универсального магазина.

## 1. Цель

Разработать отдельное веб-приложение, в котором пользователь открывает категории товаров, вращает 3D-модели, меняет доступные параметры и сохраняет выбранную комплектацию. Каталог, категории и варианты должны задаваться таблицей, а не быть зашитыми в интерфейс. Приложение должно быть пригодно для просмотра по публичной ссылке GitHub Pages.

**Принцип:** сначала универсальный 3D-каталог товаров → потом подключение к «МойБизнес2» → затем интерактивная квартира с подбором товаров в интерьере. Красивый рекламный видеоролик — отдельный продукт, не замена работающему конфигуратору.

## 2. Объем первой версии (MVP)

### 2.1 Главная страница
- Крупный первый экран с заголовком, описанием и визуальным 3D-объектом.
- Вращающиеся превью четырёх категорий из конфигурации (например, жетоны, значки, награды, кружки). Число категорий не фиксировано.
- Переход по нажатию в соответствующую категорию.
- Адаптивная навигация для ПК и телефона.
- Плавные переходы и умеренная анимация, с поддержкой настройки «уменьшить движение».

### 2.2 Каталог
- Слайдер категорий / товаров с управлением мышью, касанием и клавиатурой.
- Необязательный переключатель горизонтального и вертикального просмотра.
- Сортировка товаров по полю `sort_order`, фильтрация по категории.
- Если 3D-модель отсутствует — изображение-заглушка с подписью, а не сломанный 3D-плеер.
- Переход на отдельную карточку товара.

### 2.3 Карточка товара и 3D-просмотр
- Загрузка модели `.glb`/`.gltf` через Three.js.
- Вращение мышью/пальцем, приближение, сброс ракурса; освещение и тени.
- Название, описание, базовая цена (если предоставлена), артикул.
- Опции модели из данных: цвет, материал, размер, комплектация — только применимые к конкретному товару.
- Смена цвета/материала отображается в 3D, когда модель подготовлена для таких изменений. Для разных форм/комплектов используются отдельные модели или заранее подготовленные части.
- Кнопка «Сохранить комплектацию», формирующая состав выбранных параметров и ссылку на эту конфигурацию.
- Кнопка «Перейти в магазин» или «Отправить заявку» — на первом этапе без реальных платежей.

### 2.4 Каталог из таблицы
Для MVP таблицы CSV либо XLSX с листами:

**categories**
| id | parent_id | title | sort_order | cover_url |
|---|---|---|---|---|
| awards | | Награды | 10 | /images/awards.webp |
| medals | awards | Медали | 20 | /images/medals.webp |

**products**
| id | category_id | title | sku | price | model_url | image_url | sort_order | store_url |
|---|---|---|---|---:|---|---|---:|---|
| crystal-1 | awards | Кристалл | CR-001 | 6147 | /models/crystal.glb | /images/crystal.webp | 10 | https://example.com/product/crystal-1 |

**product_options**
| product_id | option_id | option_name | value_id | value_label | modifier | asset_url |
|---|---|---|---|---|---:|---|
| crystal-1 | material | Материал | glass | Стекло | 0 | |
| crystal-1 | material | Материал | acrylic | Акрил | -500 | /models/crystal-acrylic.glb |

**Правила импорта:**
- `id` уникален и не меняется при переименовании товара.
- `parent_id` пустой для корневых категорий; дочерние разделы вложены без лимита «ровно пять».
- Приложение проверяет обязательные поля и ссылки на родительские категории.
- Новые категории, подразделы и товары автоматически появляются в интерфейсе после обновления источника данных.
- Пустые значения опций не создают переключателей.
- Для демо: CSV/XLSX хранится в репозитории, из него во время сборки генерируется `catalog.json`, а GitHub Actions публикует обновление после push. Автоматическая синхронизация без коммита — отдельная задача (публичная Google-таблица, серверный импорт или API).
- **Важно:** просто загрузить файл через интерфейс статического сайта недостаточно для обновления каталога у всех посетителей; для постоянных изменений потребуется репозиторий, общий источник или сервер.

### 2.5 Проверка работоспособности
1. На компьютере и телефоне открывается главная без ошибок.
2. Данные категорий не зашиты в React: добавить шестой раздел в таблицу → выполнить сборку → раздел появился без изменения кода.
3. Есть минимум 3 товара, хотя бы 1 настоящая GLB-модель и по крайней мере 1 работающая опция, меняющая вид модели.
4. Товар можно вращать и приближать.
5. Выбор опций сохраняется в ссылке или `localStorage` и восстанавливается после обновления страницы.
6. При отсутствии модели отображается аккуратная заглушка.
7. Сборка `npm run build` проходит, публичная ссылка GitHub Pages работает, README содержит инструкции.

## 3. Стек для быстрого MVP

| Слой | Технология | Почему |
|---|---|---|
| База | Vite + React + TypeScript | Быстрая разработка, статическая публикация |
| Интерфейс | Tailwind CSS + Lucide | Быстрое адаптивное оформление |
| 3D | Three.js + `@react-three/fiber` + `@react-three/drei` | Просмотр GLB, камера, свет, взаимодействия |
| Состояние | React state, при усложнении Zustand | Выбранные товары/варианты |
| Каталог | CSV/XLSX → нормализованный JSON; Zod для проверки | Данные отделены от кода |
| 3D-подготовка | Blender; ИИ-генерация как дополнительный источник | Оптимизация и исправление моделей |
| Проверка | Playwright | Сценарии просмотра на разных экранах |
| Git и демо | GitHub + Actions + GitHub Pages | Открытая ссылка без VPS и сервера |

**Не включать в первую версию:** полноценную CRM, оплату, личный кабинет, сложный редактор планировок, генерацию 3D всех товаров, многопользовательское редактирование, реальные остатки. При необходимости добавить отдельно.

## 4. Интеграция с «МойБизнес2» (после демо)

Официальный сайт описывает API и интеграции, а также экспорт каталога в YML для Tilda. Это подтверждает возможности обмена данными в принципе, **но не подтверждает**, что выбранный тариф/аккаунт позволяет встраивать любое JS-приложение или делать запись заказов через API. Перед реализацией нужно получить документацию, тестовый доступ и разрешения.

Последовательность:
1. Выяснить, можно ли размещать отдельную 3D-витрину на поддомене или встраивать через `iframe`/виджет.
2. Запросить формат выгрузки товаров и ID, цены, остатки, ссылки на обычные карточки.
3. Наладить импорт каталога и сопоставить товары по устойчивому ID/SKU.
4. На первых этапах отправлять покупателя на карточку товара в основном магазине.
5. После проверки API — формировать заявки/заказы с выбранными опциями, согласовать расчёт цены и оплату.

Не хранить токены/API-ключи в публичном React-приложении или GitHub-репозитории. Операции с заказами проводить через защищённый сервер.

## 5. Будущее расширение: интерактивная квартира

**Этап 2, отдельная оценка:** загрузка полноценной геометрии квартиры; перемещение камеры по комнатам; выбор мебельных объектов из каталога; расстановка и замена мебели с сохранением размеров/координат; выбор материалов; формирование перечня выбранных товаров и заявки. Для реальной расстановки нужны настоящие 3D-модели и планировка с масштабами — фото или видео, сгенерированное ИИ, сами по себе этого не дают.

**Этап 3, отдельная оценка:** виртуальные персонажи/животные, анимированные сцены, экскурсионный маршрут, голос и музыка, экспорт проморолика. Музыка запускается пользователем, а не принудительно при открытии страницы. Права на модели, музыку и изображения должны быть подтверждены.

## 6. Порядок работ

1. **Дизайн и каркас (1–2 дня):** выбрать референс, собрать собственную систему цветов/типографики, главную и навигацию.
2. **3D-карточка (2–4 дня):** импорт GLB, вращение, ракурсы, материалы/варианты.
3. **Таблицы и конфигурации (2–3 дня):** категория из файла, подразделы, цены, выбор опций.
4. **Публикация и проверка (1–2 дня):** адаптивность, оптимизация, GitHub Pages, тесты и README.

Ориентир MVP — **примерно 1–2 недели** при исправных моделях и простых вариантах. Это не срок полной платформы с квартирой, ИИ-персонажами и интеграцией платежей.

## 8. MCP: анализ чужого интерфейса

- **PicassoWeb MCP:** https://github.com/blackridder22/PicassoWeb — анализ цветов, шрифтов, компонентов, снимков и визуальное сравнение. Экспериментальный сторонний инструмент; проверять безопасность и запускать без доступа к приватным кабинетам.
- **Официальный Playwright MCP:** https://github.com/microsoft/playwright-mcp — открытие страниц, скриншоты, клики, проверка адаптивности.
- **webEmbedding:** https://github.com/jongko54/webEmbedding — снимок и воспроизведение интерфейса. Документация прямо оговаривает, что WebGL/canvas, платежи и серверная логика не клонируются как работающее приложение.

Конфигурация MCP в Zed `~/.config/zed/settings.json` (объединить с уже существующим JSON, не перезаписывать весь файл):

```json
{
  "context_servers": {
    "picassoweb": {
      "command": "npx",
      "args": ["-y", "picassoweb", "--tools", "workflow"],
      "env": {}
    },
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"],
      "env": {}
    }
  }
}
```

В Zed также можно добавлять серверы через **Settings → AI → MCP Servers**. Нужен Node.js/npx и браузер Chromium; при первом запуске возможна загрузка пакетов и браузерных файлов.

Задача агенту: «Открой выбранный референс, опиши структуру главной страницы, размеры блоков, типографику, анимации, состояния карточки товара, адаптивное поведение. Сними скриншоты для сравнения. Реализуй собственное оформление в React; функционал 3D напиши отдельно через React Three Fiber, не копируй чужие модели и бренд».

## 9. Публикация в GitHub

```bash
npm create vite@latest 3d-showroom -- --template react-ts
cd 3d-showroom
npm install
npm install three @react-three/fiber @react-three/drei lucide-react zod
npm install -D @types/three
npm run dev
```

В `vite.config.ts` для репозитория `3d-showroom` указывать `base: '/3d-showroom/'` (если это обычный проектный GitHub Pages). В репозитории создать workflow GitHub Actions для `npm ci` → `npm run build` → загрузки `dist/` как Pages-артефакта → deploy. В `Settings → Pages` выбрать **GitHub Actions**. После публикации ссылка обычно выглядит как `https://<пользователь>.github.io/3d-showroom/`.

Для отдельных маршрутов в GitHub Pages применять hash-routing (`/#/product/...`) либо предусмотреть fallback, иначе при прямом открытии страницы может возникать 404. Публичный репозиторий не должен содержать коммерческие модели, личные данные, токены и чужие материалы без права публикации.
